# 项目概述
**目标**：基于 **ESP32-P4** 芯片，开发一款**兼容迪文 DGUS 协议生态**的高性能工业串口屏。

**核心设计哲学**：硬件分层存储 + 软件模块化解耦 + 极简健壮的启动逻辑。



## 硬件选型与核心参数

| 组件           | 型号/规格                              | 确认原因                                                     |
| :------------- | :------------------------------------- | :----------------------------------------------------------- |
| **主控芯片**   | **ESP32-P4**（双核400MHz RISC-V）      | 性能满足 1080p 解码/ LVGL 流畅运行；性价比极高；具备 PPA 图形加速器与 JPEG 硬件解码器。 |
| **片内 Flash** | **16 MB**（或 32 MB）NOR Flash         | 用于存放 Bootloader、主程序固件、DGUS 配置文件（13/14.bin）及裁剪后的字体文件。 |
| **片外存储**   | **128 MB NAND Flash**                  | 用于存放大量图片资源（底图、图标）。使用 **LittleFS** 文件系统管理，利用其磨损均衡和坏块管理能力。 |
| **屏幕规格**   | **1280 × 800** 分辨率，**RGB565** 格式 | 此为迪文主流高分屏规格，便于兼容其生态。                     |
| **PSRAM**      | **建议 32 MB 或以上**                  | 用于运行 LVGL 帧缓冲（双缓冲）、图片解码缓存及系统堆内存。   |



## 存储架构与分区规划

### 片内 16MB Flash 分区表（极简单应用分区）

| 分区名         | 类型            | 大小                  | 用途                                                |
| :------------- | :-------------- | :-------------------- | :-------------------------------------------------- |
| **bootloader** | 引导程序        | ~64KB（物理地址固定） | 不可变的工厂启动程序，负责检测 SD 卡并搬运固件。    |
| **nvs**        | 数据            | 24KB                  | 存储系统核心配置。                                  |
| **phy_init**   | 数据            | 4KB                   | 存储射频校准数据。                                  |
| **app**        | 应用程序        | **6 MB**              | 存放主程序（LVGL 8.4.0 + DGUS 协议栈 + FreeType）。 |
| **storage**    | 数据 (LittleFS) | **4 MB**              | 存放 `13.bin`（触控配置）和 `14.bin`（变量配置）。  |
| **font**       | 数据 (LittleFS) | **2 MB**              | 存放经过**裁剪（subset）** 的 TTF 字体文件。        |

> **剩余空间**：约 3.9 MB 预留，供未来固件或资源扩展使用。



### 片外 128MB NAND Flash

- **文件系统**：**LittleFS**（已在 ESP32-S3 上验证通过）。
- **存储内容**：所有底图（JPG 格式）与图标（PNG/JPG 格式）。
- **目录结构**：保留 SD 卡原始文件名（如 `013菜单.bmp`），但仅存储经过**真正旋转像素**处理后的图片文件（规避 EXIF 方向问题）。

### 关于 12.bin（拼音输入法）
- 若不需要拼音输入功能，可**不存储**。若需支持，可放入 `storage` 分区。



## 软件框架与核心机制

### LVGL 版本与图形策略
- **LVGL 版本**：**固定使用 8.4.0**。
  - **原因**：资源占用低（空载 CPU 2~3%），生态成熟，稳定性高。
  - **与 P4 的配合**：通过 `esp_lvgl_adapter` 组件启用 **PPA 硬件加速**，可实现渲染时间节省 30%，CPU 占用降低 30%。
- **图片格式策略**：
  - **背景/内容图**：优先使用 **JPG**（LVGL 解码时自动适配 RGB565）。
  - **透明图标**：使用 **PNG**。
  - **避免使用 BMP**（需严格匹配颜色深度，功能受限）。
- **UI 架构**：**单 Screen + 动态创建/销毁控件**。
  - 开机显示 0 号底图。
  - 解析 `14.bin` 创建当前页控件。
  - 翻页时：先解析新页配置，再统一清除旧控件并创建新控件（杜绝闪烁）。
- **字体渲染**：使用 **FreeType** 引擎加载片内 Flash 中的裁剪 TTF 字体文件。

### DGUS 协议兼容与变量池
- **变量池**：维护一个 **56 KB** 的静态数组（`0x0000` ~ `0x6FFF`，每个地址 2 字节）。
  - **大小端处理**：DGUS 为**大端模式**，ESP32 为小端，需在读写时做字节交换。
- **“脏标记”机制**：
  - 全局维护一个 **布尔标志**（`dgus_dirty`）。
  - 任何修改变量池的操作（串口指令或触摸事件）均将此标志置为 `true`。
  - 主循环检测到标志为 `true` 时，遍历当前页面控件，根据其绑定的变量地址从变量池取新值，刷新 LVGL 控件，然后清除标志。
  - **刷新完成后立即调用 `lv_refr_now(NULL)`** 触发渲染。

### 配置文件解析与存储
- `14.bin` 和 `13.bin` 在上电时从 SD 卡拷贝到片内 `storage` 分区。
- 翻页时，直接从片内 Flash 读取对应页面的配置块（**不重新解析整个文件**）。
- 文件名解析规则：
  - 提取数字前缀（如 `013菜单.bmp` → ID=13）。
  - 使用 `strtol(..., 10)` 强制按**十进制**解析，避免前导零被误判为八进制。

### 串口通信架构（队列缓冲方案）
- **硬件层**：使用 10 个 **256 字节**的静态缓冲区（总计 2.5 KB），而非环形缓冲区。
  - 每个缓冲区独立存放一帧完整的 DGUS 指令。
- **管理层**：维护两个队列（FreeRTOS 消息队列）：
  - **空闲队列**：存放空闲缓冲区指针（初始 10 个）。
  - **待处理队列**：存放已接收完整、待解析的缓冲区指针。
- **解析层**：状态机在中断/低优先级任务中运行，校验帧头（`5A A5`）、长度和校验和。校验通过后将指针送入待处理队列。
- **处理层**：主循环从待处理队列取指针，解析指令并更新变量池，然后释放缓冲区回空闲队列。
- **超时保护**：若接收未完成超时（如 10ms），丢弃当前半包并回收缓冲区。



## 启动与升级机制

### Bootloader 逻辑（不可变工厂固件）
- 上电后立即执行。
- **检测 SD 卡**：
  - 若存在固件文件（`app.bin`），**无视版本号**，直接覆盖写入 `app` 分区。
  - 写入前将**启动标志**置为 `invalid`，写入完成后置为 `valid`。
- **启动应用**：
  - 若标志为 `valid`，跳转至 `app` 分区执行。
  - 若标志为 `invalid`，进入死循环等待 SD 卡（100ms 周期检测），直到插入有效固件卡。

### 应用层逻辑（主程序）
- 启动后首先将启动标志置为 `valid`（告知 Bootloader 本次启动成功）。
- 初始化 LVGL、文件系统、串口、变量池。
- 扫描 SD 卡中的资源（图片、配置文件）并拷贝至对应分区。
- 进入主循环：处理串口指令 → 处理触摸事件 → 更新 UI。

### 版本号管理
- **仅用于展示与追溯**（通过串口指令或“关于”菜单读取）。
- **不参与升级决策**（客户有权锁定旧版本，直接覆盖即可）。



## 关键避坑与细节

| 问题点                           | 确认解决方案                                                 |
| :------------------------------- | :----------------------------------------------------------- |
| **JPG 旋转不生效（宽高不交换）** | Windows 仅修改 EXIF 方向标记，LVGL 不识别。需在 PC 上用 **IrfanView/XNView 的无损旋转功能** 真正旋转像素后再存入设备。 |
| **LVGL v9 资源占用高**           | 确认使用 **v8.4.0**，空载 CPU 仅 2~3%，更符合工业屏需求。    |
| **NAND Flash 坏块/磨损**         | 使用 LittleFS 文件系统，自带坏块管理和磨损均衡；片外 NAND 仅用于存储图片，写入频率极低，风险可控。 |
| **双 OTA 分区冗余**              | 否决，使用 **单应用分区 + 强制覆盖** 模式，逻辑更清晰，无回滚混淆问题。 |
| **字体文件过大**                 | 使用 `pyftsubset` 工具裁剪字库，仅保留界面实际用到的字符（目标 ≤ 2MB）。 |



## 商业与法律考量

- **兼容迪文生态**：产品可宣传为“**兼容 DWIN DGUS 配置系统**”，但宣传和包装上**不得直接使用“DGUS”或“迪文”作为品牌名称**。
- **风险规避**：市场上存在大量迪文兼容屏（如淘晶驰、大彩），证明该路径可行。建议量产前进行专利检索，并采用“转换工具”等方式规避直接复制风险。
