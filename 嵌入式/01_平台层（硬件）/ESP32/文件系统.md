# ESP32-P4 多存储文件系统笔记

## 项目概述

**目标**：基于 **ESP32-P4** 芯片，构建一套面向工业嵌入式设备的多存储文件系统方案，覆盖 **片上 NOR Flash、板载 NAND Flash、外接 SD 卡** 三类介质。

**核心设计哲学**：介质分层存储 + 文件系统各司其职 + 统一 VFS 接口 + 掉电安全优先。

**关键结论**：
- 片内 NOR：**LittleFS**（首选）或 SPIFFS。
- 板载 NAND：**UFFS**（裸 NAND 首选）；若沿用已验证的 LittleFS，必须确保底层坏块管理。
- 外接 SD 卡：**FAT32**，用于跨平台交换与资源导入。
- 应用层通过 ESP-IDF VFS 使用统一 POSIX API 访问。


## 硬件选型与核心参数

| 组件                | 型号/规格                           | 确认原因                                                     |
| :------------------ | :---------------------------------- | :----------------------------------------------------------- |
| **主控芯片**        | **ESP32-P4**（双核 400 MHz RISC-V） | 支持 VFS、SDMMC、SPI、DMA，适合多文件系统并行挂载。          |
| **片内 NOR Flash**  | **16 MB**                           | 存放 Bootloader、分区表、NVS、应用固件、DGUS 配置、裁剪字体。 |
| **板载 NAND Flash** | **256 MB**                          | 存放大量图片资源（底图、图标），容量大、成本低，但需坏块管理与 ECC。 |
| **外接 SD 卡**      | **32 GB**                           | 用于资源导入、固件升级、日志导出、PC 直接读写。              |
| **PSRAM**           | **建议 32 MB**                      | 用于文件缓存、LVGL 帧缓冲、图片解码缓存。                    |
| **文件系统组件**    | LittleFS / UFFS / FATFS             | ESP-IDF 原生支持 FATFS；LittleFS、UFFS 通过组件集成。        |


## 存储架构与分区规划

### 片内 16 MB NOR Flash 分区表

| 分区名              | 类型     | 大小     | 文件系统     | 用途                                              |
| :------------------ | :------- | :------- | :----------- | :------------------------------------------------ |
| **bootloader**      | 引导程序 | ~64 KB   | 无           | 不可变工厂启动程序，检测 SD 卡并搬运固件。        |
| **partition-table** | 分区表   | 4 KB     | 无           | 描述 Flash 分区布局。                             |
| **nvs**             | 数据     | 24 KB    | NVS          | 存储系统核心配置、启动标志、校准参数。            |
| **phy_init**        | 数据     | 4 KB     | 无           | 射频校准数据。                                    |
| **app**             | 应用程序 | **6 MB** | 无           | 主程序：LVGL 8.4.0 + DGUS 协议栈 + FreeType。     |
| **storage**         | 数据     | **4 MB** | **LittleFS** | 存放 `13.bin`（触控配置）、`14.bin`（变量配置）。 |
| **font**            | 数据     | **2 MB** | **LittleFS** | 存放裁剪后的 TTF 字体文件。                       |
| **reserved**        | 预留     | ~3.9 MB  | 无           | 未来固件或资源扩展。                              |

> **注意**：NVS 建议独立分区，不与其他文件系统混用；LittleFS 的 block size 应与 NOR 擦除扇区（通常 4 KB）匹配。

### 板载 256 MB NAND Flash

- **推荐文件系统**：**UFFS**（裸 NAND 首选）。
- **备选文件系统**：**LittleFS**（若底层已实现坏块管理与 ECC）。
- **存储内容**：所有底图（JPG）与图标（PNG/JPG）。
- **目录结构**：保留原始文件名，如 `013菜单.bmp`，但仅存储真正旋转像素后的图片，规避 EXIF 方向问题。
- **关键要求**：
  - NAND 存在出厂坏块，必须进行坏块管理。
  - 必须启用 ECC 纠错。
  - 不能直接 XIP，不能像 NOR 一样随机字节访问。

### 外接 32 GB SD 卡

- **文件系统**：**FAT32**。
- **原因**：PC、相机、读卡器均兼容，数据可直接交换。
- **用途**：
  - 固件升级包 `app.bin`。
  - 资源包：图片、字体、`13.bin`、`14.bin`。
  - 运行日志导出。
- **注意**：
  - FAT32 单文件最大 4 GB，32 GB 卡完全够用。
  - 大容量卡可能出厂为 exFAT，需先格式化为 FAT32。
  - FAT32 无原生掉电保护，需依赖 SD 控制器、`esp_jrnl` 和应用层策略。


## 文件系统选型对比

| 文件系统     | 适用介质     | 掉电保护                          | 坏块管理   | 磨损均衡   | 目录支持 | PC 兼容 | RAM 占用   |
| :----------- | :----------- | :-------------------------------- | :--------- | :--------- | :------- | :------ | :--------- |
| **LittleFS** | NOR / NAND   | **强**：COW + 元数据对 + 原子提交 | 依赖底层   | 内建       | 支持     | 低      | 固定，较低 |
| **SPIFFS**   | NOR          | 弱，掉电可能损坏                  | 无         | 内建       | 不支持   | 低      | 很低       |
| **UFFS**     | 裸 NAND      | **强**：日志 + 自动回滚           | 内建       | 内建       | 支持     | 低      | 较低       |
| **FAT32**    | SD 卡 / eMMC | **无原生保护**                    | 依赖控制器 | 依赖控制器 | 支持     | 极高    | 中等       |


## 软件框架与核心机制

### VFS 统一挂载

ESP-IDF 通过 VFS 将不同文件系统挂载到不同路径：

| 挂载点    | 文件系统        | 介质      | 典型用途         |
| :-------- | :-------------- | :-------- | :--------------- |
| `/flash`  | LittleFS        | 片内 NOR  | 配置、字体       |
| `/nand`   | UFFS / LittleFS | 板载 NAND | 图片资源         |
| `/sdcard` | FAT32           | SD 卡     | 升级、导入、导出 |

应用层使用 `fopen`、`fread`、`fwrite`、`f_close` 等 POSIX API，无需关心底层差异。

### 挂载顺序建议

1. 初始化 NVS。
2. 挂载片内 LittleFS：`/flash`。
3. 初始化 SPI NAND，挂载 UFFS 或 LittleFS：`/nand`。
4. 初始化 SDMMC，挂载 FAT32：`/sdcard`。
5. 若 SD 卡支持热插拔，需注册 CD 引脚中断，卸载后再重新挂载。

### 配置文件解析与存储

- `14.bin` 和 `13.bin` 上电时从 SD 卡拷贝到片内 `storage` 分区。
- 翻页时直接从片内 Flash 读取对应页面的配置块，不重新解析整个文件。
- 文件名解析规则：
  - 提取数字前缀，如 `013菜单.bmp` → ID = 13。
  - 使用 `strtol(..., 10)` 强制按十进制解析，避免前导零被误判为八进制。

### 串口通信与文件系统交互

- 串口接收 DGUS 指令，更新变量池。
- 若指令涉及文件操作，例如更新图片、读取配置，则通过 VFS 访问对应文件系统。
- 日志写入建议优先写 SD 卡，减少 NOR / NAND 写入次数。


## 掉电保护机制详解

### LittleFS：设计上强保证

LittleFS 的掉电安全是内建核心特性，通过 **写时复制（COW）** 和 **原子提交** 实现。

- **元数据对机制**：每个元数据对包含两个块，一个主块，一个备份块。
- **追加操作**：新数据追加到日志末尾，不覆盖旧数据。追加过程中断电，原始条目依然完好。
- **紧凑化（垃圾回收）**：块满时，将有效数据复制到新块，所有更改写入第二个块，只有提交校验和被写入后，新数据才生效。
- **分裂**：块满且无垃圾可回收时，元数据对分裂。先在新元数据对中准备，再在原始元数据对提交中插入尾指针，保证掉电安全。
- **CRC 校验**：检测因掉电或其他写入问题导致的损坏。

> **结论**：LittleFS 在 NOR 上可提供高可靠掉电保护；在 NAND 上使用时，底层必须正确处理坏块和 ECC。

### UFFS：日志式回滚保证

UFFS 是专为 NAND Flash 设计的日志文件系统。

- **核心保证**：当写入操作返回成功时，数据必定已安全保存到 Flash。
- **日志机制**：记录文件系统操作意图。执行过程中掉电，重启后根据日志将未完成操作回滚。
- **无需垃圾回收**：减少后台 GC 与掉电事件交织产生的复杂状态。
- **坏块管理**：自动处理出厂坏块和运行时块失效。
- **磨损均衡**：均匀分配写入，延长 NAND 寿命。

> **结论**：UFFS 是裸 NAND 上掉电保护最省心的方案之一。

### FAT32：协议上无保证，依赖多层缓解

FAT32 本身不是日志文件系统，不具备写操作原子性。

- **撕裂写风险**：写入过程中掉电，可能导致 FAT 表、目录项、数据区不一致。
- **SD 卡控制器层**：工业级 SD 卡可能内置掉电鲁棒性算法，在电源切断时完成或放弃当前写入。
- **ESP-IDF 软件层**：`esp_jrnl` 可为 FatFS 提供事务日志，显著提高掉电可靠性，但官方明确说明仍无法保证 100% 恢复。
- **应用层策略**：
  - 写临时文件，完成后原子重命名。
  - 频繁调用 `f_sync()`。
  - 关键数据双分区备份。
  - 增加校验和，启动时校验。
  - 只读挂载，避免运行中写入。

> **结论**：SD 卡上的 FAT32 适合交换和导入，不适合作为高可靠运行时数据库。


## 启动与升级机制

### Bootloader 逻辑

- 上电后立即执行。
- 检测 SD 卡：
  - 若存在固件文件 `app.bin`，无视版本号，直接覆盖写入 `app` 分区。
  - 写入前将启动标志置为 `invalid`，写入完成后置为 `valid`。
- 启动应用：
  - 若标志为 `valid`，跳转至 `app` 分区执行。
  - 若标志为 `invalid`，进入死循环等待 SD 卡，100 ms 周期检测。

### 应用层逻辑

- 启动后首先将启动标志置为 `valid`。
- 初始化 LVGL、文件系统、串口、变量池。
- 扫描 SD 卡中的资源，拷贝至对应分区：
  - 图片资源 → NAND `/nand`。
  - 配置文件 → NOR `/flash/storage`。
  - 字体文件 → NOR `/flash/font`。
- 进入主循环：处理串口指令 → 处理触摸事件 → 更新 UI。

### 版本号管理

- 仅用于展示与追溯。
- 不参与升级决策，客户可锁定旧版本，直接覆盖。


## 性能优化建议

| 优化点                         | 建议                                                |
| :----------------------------- | :-------------------------------------------------- |
| **LittleFS block size**        | 与 NOR 擦除扇区匹配，通常 4 KB。                    |
| **LittleFS cache / lookahead** | 适当增大，减少读放大。                              |
| **UFFS 页/块大小**             | 与 NAND 物理页、擦除块匹配。                        |
| **FATFS 长文件名**             | 使用 `CONFIG_FATFS_LFN_HEAP`，按需设置最大长度。    |
| **FATFS 同步策略**             | 根据可靠性需求配置 `CONFIG_FATFS_IMMEDIATE_FSYNC`。 |
| **SDMMC 总线**                 | 使用 4-bit 模式，提高吞吐。                         |
| **DMA**                        | 启用 DMA，降低 CPU 占用。                           |
| **图片格式**                   | 背景图优先 JPG，透明图标用 PNG。                    |
| **字体裁剪**                   | 使用 `pyftsubset` 裁剪字库，目标 ≤ 2 MB。           |


## 关键避坑与细节

| 问题点                     | 确认解决方案                                                 |
| :------------------------- | :----------------------------------------------------------- |
| **NAND 坏块**              | 裸 NAND 必须使用 UFFS 或底层坏块管理；LittleFS 不能自动处理物理坏块。 |
| **NAND ECC**               | 必须启用硬件或软件 ECC，否则数据不可靠。                     |
| **LittleFS 在 NAND 上**    | 若沿用已验证方案，需确认块设备驱动已处理坏块跳过和 ECC。     |
| **FAT32 单文件 4 GB 限制** | 大文件需分卷或改用 exFAT，但 exFAT 在嵌入式端兼容性较差。    |
| **SD 卡热插拔**            | 检测 CD 引脚，先卸载再挂载，避免文件系统损坏。               |
| **掉电撕裂写**             | LittleFS / UFFS 内建保护；FAT32 需 `esp_jrnl` + 应用层校验。 |
| **SPIFFS 不再维护**        | 新项目优先 LittleFS，SPIFFS 仅用于极低 RAM 场景。            |
| **NVS 磨损**               | 不要频繁写 NVS，配置变更应合并写入。                         |
| **挂载失败处理**           | 不要默认格式化，先尝试恢复；必要时提供工厂格式化指令。       |
| **多文件系统文件描述符**   | 注意 VFS 最大 FD 数量，及时关闭文件。                        |
| **日志写入**               | 优先写 SD 卡，减少 NOR / NAND 擦写次数。                     |


## 总结

| 存储介质              | 推荐文件系统                       | 掉电保护           | 核心原因                       |
| :-------------------- | :--------------------------------- | :----------------- | :----------------------------- |
| **16 MB NOR Flash**   | **LittleFS**（首选）/ SPIFFS       | 高，设计强保证     | 磨损均衡、掉电保护、支持目录。 |
| **256 MB NAND Flash** | **UFFS**（裸 NAND 首选）/ LittleFS | 高，日志回滚或 COW | 坏块管理、ECC、掉电安全。      |
| **32 GB SD 卡**       | **FAT32**                          | 低，协议无保证     | 跨平台兼容，PC 直接读写。      |

ESP32-P4 通过 VFS 统一挂载这些文件系统，应用层可用相同 POSIX API 操作。若对数据完整性有严格要求，应优先选用 **LittleFS** 和 **UFFS**；SD 卡上的 FAT32 适合交换与导入，但需接受其固有风险，并通过硬件选型和软件策略尽力缓解。
