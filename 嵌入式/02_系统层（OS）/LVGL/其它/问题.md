### 键盘

屏幕上有大量按钮，其中一个按钮按下后会弹出一个半屏键盘。

键盘存在期间禁用所有其他按钮控件的触摸响应，键盘关闭后恢复原样。

如何处理？

-   使用透明遮罩



追问：键盘存在期间虽然禁用所有其他控件的触摸响应，但是仍然需要响应串口通讯的特定指令。

存在有一个通用的页面切换函数，使用特定的串口指令触发。

现在，在键盘存在期间收到指令，该函数被触发，要切换到其他页面，并且在切换回这个界面时，要求是处于键盘不存在或隐藏的收起状态，要如何处理？

-   页面SCREEN注册 `LV_EVENT_SCREEN_UNLOADED ` 回调，在切换页面时会自动触发键盘的删除或隐藏回调，执行清理。



### 字体

Flash 总预算不超过 16MB，GBK 汉字集，要求 14~50 号可变字号，同一屏幕可能出现多种字号。

要求：14 号小字必须清晰无锯齿（不能模糊），且 50 号大字放大后不能出现明显锯齿。

CPU 算力充足，RAM 不足 512KB。

-   混合策略：14~20 号使用点阵字库，清晰锐利。24~50 号使用矢量字体，在运行时缩放。
-   点阵部分：GBK 16 号点阵约 1MB，20 号约 1.5MB。选 14、16、18、20 四套共约 5MB。
-   矢量部分：取 GBK 子集（常用 6000 字），瘦身后的 TTF 约 2~3MB。总 Flash 约 8MB，符合预算。
-   抗锯齿与清晰度：
    -   小字号矢量无 hinting 关闭抗锯齿会发虚，所以保留点阵是明智的。
    -   大字号矢量开启抗锯齿（`LV_FREETYPE` 渲染时设置），边缘平滑。

-   CPU 开销：点阵直接拷贝，零开销；矢量渲染用 FreeType 缓存字形位图，设置缓存大小例如 256KB，LRU 淘汰。每帧确保不超过一定时间片渲染字形。



## 高优先级问题

### 双核串口通信与 UI 更新

双核 MCU，运行 RTOS。需要将串口收到的数据实时显示在 LVGL 界面上。

核 0 使用串口 DMA 接收数据，波特率高，连续收到大量数据帧（比如每帧 128 字节，间隔 2ms），并且解析协议。

核 1 负责渲染。

已知核 1 渲染一帧需要耗时 8ms，此时串口会不断地有新数据到达，如何保证最新数据不被丢失，且核 1 渲染不撕裂？

-   使用双缓冲区，分别为代表最新数据的缓冲区和正在渲染的缓冲区，核 0 将解析后的数据轮流放入代表最新数据的缓冲区，核 1 需要数据渲染时，将代表最新数据的缓冲区转化身份为正在渲染的缓冲区。
-   这样核 0 每次都可以把最新的数据写入缓冲区，核 1 也只需要每次读取最新的数据，无需把过去积压的数据也一起读取显示出来。



### 页面与定时器

在标准的指针钟表 UI 主页面下，已知拥有一个可信的标准RTC时间，精确到毫秒。

要求秒针需要平滑移动，而非每秒跳变一格。

并且，页面不可见时不消耗任何 CPU 更新秒针，但页面重新可见的瞬间，秒针必须立即在正确位置。

-   使用 LV_EVENT_SCREEN_LOADED 和 LV_EVENT_SCREEN_UNLOADED 来创建和删除定时器。
-   大约16.7ms移动一次就是60fps，可以实现平滑移动的效果，保证定时器的频率足够高即可。
-   每个周期内获取标准RTC时间用来确定指针方向。



## 中优先级问题

### 图片格式

针对算力强但剩余 RAM 和 Flash 都极小的MCU，需显示一张图片。

要求：这张图片未来需要更新，不能重新编译固件。

你会选什么格式？如何实现？解码时内存不够怎么办？

-   选择 带逐行解码的 JPEG（SJPG） 或 定制分块位图。
-   针对不编译进固件：将 .sjpg 文件放入文件系统，LVGL 通过 `lv_img_set_src` 加载，设置 `LV_IMG_CACHE_DEF_SIZE` 为 0 或极小，避免缓存占用 RAM。
-   内存不够降级方案：将图片切割为 50x50 瓦片，分别解码显示，组成完整 logo，但需要精确布局。

## 拓展问题

### 内存卡升级

设备已出货，需要在内存卡内读取数据更新一个包含图片和字体的 LVGL 主题包。

你会如何设计这个存储分区最大限度利用储存空间？使用何种校验机制？

假设校验工程中断电，又要如何处理？

-   最大限度利用储存空间：一个极小的下载分区，专门运行下载固件的程序，每次都首先启动这个分区的程序，检测是否有新的固件需要更新，若有，下载更新校验完毕后进入应用程序区域，若无，直接进入应用程序区域。

-   使用何种校验机制：CRC32/SHA256 校验。
-   下载分区为只读，不会被破坏，再次下载即可。
